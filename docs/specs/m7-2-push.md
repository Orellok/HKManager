# M7.2 – Web Push (NOTIF-4..16)

Source: SPEC.md 5.13 NOTIF-4..16, 5.14 (settings), 6 (`push_subscriptions`, `reminder_runs`), 7 (PWA, Push), 10 (tests), 13 VERIFY-04; docs/verify/VERIFY-04-web-push.md; docs/PROGRESS.md lead decisions 2026-11-23 (VERIFY-04, M7 split) and the M7.1 carry (install suggestion, NOTIF-13). Criteria set by the lead under the owner's pre-approval.

## Acceptance criteria

### Data and schedule
1. Migration creates `push_subscriptions` (SPEC 6 columns; `endpoint` unique, https on a known push service host; `p256dh` / `auth` base64url) and `reminder_runs` (SPEC 6 columns, `run_date` unique). RLS: a user reads and deletes only their own subscriptions (and must be allowlisted); writes go through `save_push_subscription()` (SECURITY DEFINER, allowlisted caller, upsert by endpoint, the endpoint moves to the caller). `reminder_runs` is service-role only.
2. The migration fails with a clear message if `pg_cron` or `pg_net` is not available (proves VERIFY-04 on the staging migrations run). It schedules two pg_cron jobs, 06:00 and 07:00 UTC (NOTIF-16), each calling `invoke_daily_reminders()`, which POSTs to the Edge Function via `pg_net` with a shared secret. The function URL and the secret live in Supabase Vault: the secret is generated by the migration (never in the repo), the URL is set by `configure_push_reminders(url)` (service role / postgres only). A missing URL fails the job run loudly (cron run log) without sending.

### Sending (Edge Function `push`)
3. Daily run (secret header, constant-time check against Vault): exits without sending unless the local hour in `Asia/Jerusalem` is 9 (summer and winter time); claims `reminder_runs(run_date)` first, so a second call on the same local date sends nothing (NOTIF-9); counts open, not deleted tasks due tomorrow / today / overdue (NOTIF-7; done, cancelled, deleted and undated tasks never count); sends nothing when all three are 0; otherwise one summary per subscription (NOTIF-6, 8) and records counts, sent and failed.
4. Summary text (NOTIF-8, 15): only non-empty groups, order today · tomorrow · overdue, e.g. "2 משימות להיום · 1 למחר · 3 באיחור" (first group carries the noun; 1 → "משימה אחת"). A single task in total: its title and its state ("להיום" / "למחר" / "באיחור"). Never client names, addresses or amounts. Notification title "HKManager"; click target `/tasks` (NOTIF-10).
5. Delivery: Web Push per RFC 8291 (aes128gcm) and RFC 8292 (VAPID, ES256) implemented with Web Crypto only (no new dependency), `TTL` 12 h, `Urgency: high`. 404/410 deletes the subscription; any other failure is counted and logged by status code only (no endpoint, no payload) and does not stop the others (NOTIF-11); 2xx stamps `last_success_at`. VAPID keys and the subject come from Edge Function secrets; a missing secret fails the run without sending.
6. Test push (NOTIF-14): the function accepts a caller's user JWT and an endpoint; it sends a fixed test message only to that endpoint and only if it is the caller's own subscription (RLS), with click target `/settings`.

### App
7. Settings section "התראות במכשיר זה" (NOTIF-5, 13, 14) shows the device state – פעיל / כבוי / חסום בדפדפן / לא נתמך – with guidance per state. "הפעל התראות במכשיר זה" asks permission only on that click (never on load), subscribes with the public VAPID key and saves the subscription; "כבה התראות במכשיר זה" unsubscribes and deletes it; "שלח התראת בדיקה" (active only) calls the function through a Server Action and reports sent / failed. An existing browser subscription is re-saved on load. Without a configured public key the state is "לא נתמך" with a configuration hint. Errors are shown beside the section, in Hebrew, announced; buttons show progress and block repeats.
8. Install suggestion (NOTIF-13, M7.1 carry): when the app is not running as an installed PWA, the section suggests installing it (not required for Push); if Chrome offered `beforeinstallprompt`, an "התקנת האפליקציה" button opens Chrome's prompt.
9. Server Actions validate input with zod (endpoint https on a known push host, ≤ 2048 chars; p256dh 65 bytes uncompressed P-256; auth 16 bytes) and require an allowlisted session.

### Service worker
10. `public/sw.js` gains `push` (shows the notification from a JSON payload with RTL / Hebrew, the app icon and a tag; a malformed payload shows a generic text) and `notificationclick` (focuses an open app window or opens one at the payload's path; any path that is not same-origin falls back to `/tasks`). Static-only caching is unchanged.

### Operations
11. `scripts/generate-push-keys.mts` (Node built-ins only) writes a VAPID key pair and subject to a git-ignored, owner-only (0600) env file for `supabase secrets set --env-file`, prints only the public key and the next steps, never the private key. Edge Function deploy (`--use-api`, no JWT verification at the gateway) and `configure_push_reminders` run in the staging and production migrations workflows after the migrations, printing no data. `docs/setup/push.md` lists the owner steps.
12. Owner device checklist (Hebrew) = VERIFY-04 file checklist, final acceptance, not a blocker for DONE.

### General
13. No new dependency; Hebrew RTL; WCAG 2.1 AA; 360/412/1280 without horizontal scroll. Tests: unit (RFC 8291 vector, VAPID JWT verification, summary text, hour/DST check, zod rules, SW push/click logic, key script), integration (RLS, save/delete, idempotency of a double run, hour-9 only in summer and winter, no tasks → nothing, all group combinations, 410 deletion, other failure counted, done/cancelled/undated excluded, cron jobs exist, extension check), E2E (settings states with stubbed browser APIs, enable / test / disable against a mock function, real SW shows a pushed notification). Names include M7.2-n.
